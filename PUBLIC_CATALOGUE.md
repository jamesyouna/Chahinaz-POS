# Public catalogue

The POS remains the source of truth. The customer website reads only the dedicated, unauthenticated catalogue API. Public responses are projections and never serialize JPA entities.

## API

- `GET /api/public/catalogue/products`
- `GET /api/public/catalogue/products/{uuid}`
- `GET /api/public/catalogue/categories`
- `GET /api/public/images/{safe-generated-key}`

Product queries accept `search`, `category`, `featured`, `newArrival`, `availability`, `page`, `size` (maximum 200), and `sort` (`name`, `price`, `-price`, `updated`). The stable product UUID is used as the public identifier because existing product identifiers are already random UUIDs rather than sequential database IDs.

Public product fields are: `id`, `sku`, `name`, `description`, `categoryId`, `categoryName`, `sellingPriceUsd`, `imageUrl`, `inStock` (legacy compatibility), `availability`, `featured`, `newArrival`, and `updatedAt`. Cost, exact quantity, threshold, suppliers, employees, sales, audit, register and payment data are excluded by the DTO.

Public category fields are only `id` and `name`.

A product is public only when its category is active, the product is active, and publication is `PUBLISHED`. Stock at or below zero is `OUT_OF_STOCK`; positive stock at or below the internal threshold is `LOW_STOCK`; other positive stock is `IN_STOCK`. Cart activity never changes POS stock.

Managers publish from **Products** after making both the category and product active. Changes appear after the website's next request, normally within the 30-second catalogue cache window. JSON is public-cacheable for 30 seconds with revalidation; categories for two minutes; images for 30 days. Image keys are generated by the existing validated upload service and public image access also requires a currently published product.

## CORS and deployment

`POS_PUBLIC_CATALOGUE_ORIGINS` defaults to the two Chahina'z website origins. It applies only to `/api/public/**`, allows read operations, and does not permit credentials. Authenticated POS routes retain session authentication and CSRF.

For local development, run the POS on `http://localhost:8080` and the website on `http://localhost:4173`. Add the local website origin to `POS_PUBLIC_CATALOGUE_ORIGINS` while developing.

For the store deployment, use a Cloudflare Tunnel with `api.chahinazdollar.store` and configure its ingress to forward only `/api/public/catalogue/*` and `/api/public/images/*` to `http://127.0.0.1:8080`; the catch-all ingress must return HTTP 404. Never forward PostgreSQL or the complete POS. The tunnel and DNS require the store owner's Cloudflare account and are manual steps. A hosted backend is more resilient to store power or internet outages, while the tunnel is simpler and keeps the current store database authoritative. The initial recommendation is the restricted tunnel, plus monitoring and existing off-site backups.

The public site will show a retryable error whenever the tunnel or store PC is unavailable. Live production synchronization is not operational until the tunnel, DNS hostname, and website deployment are configured.
